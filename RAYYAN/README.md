# RAYYAN — ريّان: نظام الري الذكي (Full-Stack Machine Learning)

> **تعتمد نتائج النماذج الحالية على بيانات محاكاة، ولا تمثل دقة مثبتة في بيئة زراعية حقيقية.**

ريّان تطبيق ويب متكامل يتنبأ برطوبة التربة ويساعد في قرارات الري. يصدر قرارًا مفسرًا (ري / تأجيل / فحص الحساس) مع كمية الماء ومدة الري، ويحفظ كل قرار وتنبؤ في SQLite.

| الطبقة | التقنية |
|---|---|
| الواجهة | React 19 + TypeScript + Tailwind CSS v4 + d3، عربية بالكامل RTL |
| الخادم | **FastAPI** + Pydantic + Uvicorn |
| التعلم الآلي | scikit-learn |
| قاعدة البيانات | SQLite |
| معالجة الصور | NumPy + Pillow |

## نظامان ونموذجان مستقلان

| | ثيل البرمودا | المحاصيل الأربع |
|---|---|---|
| البيانات | حزمة ريّان 2024–2025 (`original_upload.zip`) | `RAYYAN_ML_Ready.xlsx` — 2024-10 إلى 2026-10 |
| المناطق | منطقتان، 5 م² لكل منهما | نخيل مجدول، برسيم، خضار في بيوت محمية، نجيل |
| النموذج | Random Forest: تغير الرطوبة بعد ساعتين من الرية | Random Forest **هجين** يصحح معادلة موازنة الماء: الرطوبة % بعد 6 ساعات |
| القرار والكمية | قواعد المشروع `rule_v1` | FAO-56 الفصل 8 (TAW، RAW، Dr) بقيم المنطقة من الملف |
| الاختبار | RMSE 0.00244 m³/m³، R² 0.827 (خط الأساس 0.00598) | RMSE 0.644 نقطة، MAE 0.468، R² 0.978 (بقاء الرطوبة 2.227، موازنة الماء 0.661) |

لم تُخلط بيانات النظامين، ولم يُفترض تطابق المحاصيل. التفاصيل في [`docs/CROPS_MODEL.md`](docs/CROPS_MODEL.md) و[`docs/EVALUATION.md`](docs/EVALUATION.md).

## 1. متطلبات التشغيل

- **Windows 10/11** مع **Python 3.11 أو أحدث** (اختُبر على Python 3.14). يكفي مشغل `py` الذي يأتي مع Python من python.org.
- **Node.js 18 أو أحدث** (اختُبر على Node 24)، **لتعديل الواجهة فقط**. الواجهة مبنية مسبقًا في `frontend/dist`، فالتشغيل لا يحتاج Node.
- متصفح حديث (Edge أو Chrome).

## 2. تثبيت المكتبات

```powershell
cd RAYYAN
py -3 -m pip install -r requirements.txt        # الخادم والتعلم الآلي
py -3 -m pip install -r requirements-dev.txt    # + pytest للاختبارات
cd frontend; npm install; cd ..                   # الواجهة (لتعديلها فقط)
```

`run.bat` يتحقق من المكتبات وحده. إن نقصت شيء أنشأ بيئة `.venv` وثبّت `requirements.txt` فيها.

## 3. التشغيل بأمر واحد

```powershell
.\run.bat
```

يجهز `run.bat` ما ينقص (البيانات، النماذج، معالجة الصور)، ثم يشغل الخادم ويفتح **http://127.0.0.1:8000**.

| الأمر | ماذا يفعل |
|---|---|
| `run.bat` | تشغيل التطبيق كاملًا |
| `run.bat --no-browser --port 9000` | منفذ آخر دون فتح المتصفح |
| `run.bat --test` | كل الاختبارات |
| `run.bat --rebuild --setup-only` | إعادة كل شيء من الملفات الأصلية: البيانات والتحقق من البصمات وتدريب كل النماذج |

## 4. تشغيل الـBackend وحده

```powershell
py -3 -m uvicorn backend.main:app --reload --port 8000     # للتطوير
py -3 -m backend.main                                       # تشغيل عادي
```

| الرابط | المحتوى |
|---|---|
| `http://127.0.0.1:8000/api/swagger` | Swagger التفاعلي من FastAPI |
| `/api/redoc` | ReDoc |
| `/api/docs` | التوثيق العربي |
| `/api/openapi.json` | المخطط |

التوثيق المكتوب لكل النقاط الـ35 في [`docs/API.md`](docs/API.md)، ويُولد بالأمر `py -3 scripts\gen_api_docs.py`.

**قواعد عامة للـAPI:**
- **الأخطاء** موحدة: `{"error": {"code", "message", "details"}}` مع رسالة عربية لكل حقل.
  - `422`: مدخلات غير صالحة.
  - `400`: JSON تالف.
  - `404`: معرف أو يوم غير موجود.
  - `503`: نموذج غير متاح.
  - `500`: خطأ داخلي، يُسجل نصه.
- **السجل:** كل طلب يُسجل في `app_requests` مع رقم في ترويسة `X-Request-ID`.

## 6. تدريب النماذج

```powershell
py -3 ml\training\train_crops_model.py      # المحاصيل الأربع: 57 إعدادًا + خطوط الأساس (~1.5 دقيقة)
py -3 ml\training\train_response_model.py   # البرمودا
py -3 ml\training\train_v2_model.py         # النموذج الثاني الأصلي (للمرجع)
py -3 image_processing\main.py              # معالجة الصور الميدانية كمصفوفات NumPy
```

**ما ينتجه كل تدريب:**
- النموذج (`*.joblib`) وتقرير المقاييس (`*_metrics.json`) في `ml/saved_models/`.
- تنبؤات كل سجل في SQLite.
- الخادم يحمّل النماذج عند تشغيله، والواجهة تقرأ المقاييس من التقرير نفسه، فلا توجد أرقام مكتوبة يدويًا.

**قواعد التدريب في كل النماذج:**
- تقسيم زمني.
- المعالجة داخل Pipeline تتعلم من التدريب فقط.
- منع المدخلات المتحققة بعد القرار.
- الاختيار على التحقق فقط، ومقارنة مع خطوط الأساس.
- فحوص تسرب تُوقف التدريب إن فشلت.

## 7. استخدام التطبيق

في كل صفحة مبدّل بين **ثيل البرمودا** و**المحاصيل الأربع**.

| الصفحة | ماذا تجدين فيها |
|---|---|
| **لوحة التحكم** | لكل منطقة: الرطوبة الحالية، والهدف، والمتوقعة بعد الري (مقطع تربة ومؤشر رطوبة متحرك)، والتوصية، والكمية المقترحة، والحالة. يضاف إليها: اتجاه 30 يومًا، والمخطط مقابل المنفذ، والتنبيهات، وآخر القرارات. اختيار أي يوم. |
| **توصية الري** | نموذج إدخال: المنطقة، والرطوبة، والطقس، وp، والهدف، والميزانية. النتيجة: القرار وأسبابه بالأرقام، وطريقة حساب الكمية والمدة، والرطوبة المتوقعة دون ري ومع الري، ومنحنى الاستجابة، وما سجله الملف لنفس اليوم للمقارنة. «احفظي» يسجلها في SQLite. |
| **المحاكاة** | حتى 6 سيناريوهات (الكمية، والرطوبة الابتدائية، والطقس) تُشغَّل على النموذج الفعلي في الخادم وتُحفظ. منحنى الاستجابة يميز نطاق التدريب. |
| **أداء النماذج** | لكل نموذج: النوع، وأعداد التدريب والاختبار، وMAE/RMSE/R²، ومقارنة خطوط الأساس (المحسوبة والمبلغ عنها)، والمتنبأ مقابل الفعلي، والخطأ حسب المنطقة، وأهمية المدخلات، واختيار النموذج، وفحوص التسرب. |
| **المناطق والمحاصيل** | المناطق الست. اختيار منطقة يعرض بياناتها ويشغّل **نموذجها** (نموذج البرمودا أو نموذج المحاصيل). |
| **السجل** | القرارات والتنبؤات والمحاكاة المحفوظة بالتاريخ والوقت والمنطقة والنتيجة، مع البحث والتصفية والتفاصيل. |
| **الموقع والمعرض** | الموقع، والأجهزة الافتراضية، وأصل كل جدول، والبيانات الميدانية الناقصة. يضاف إليها معرض الصور الأصلية وتحليلها: رمادي، وقناع الغطاء الأخضر، والحواف، ومؤشر الأخضر من `image_processing`. |

## 8. حدود البيانات والنماذج

- **كل البيانات محاكاة** (مولدات الحزمتين)، ولا توجد حساسات أو عدادات مركبة. المقاييس تقيس تعلم المحاكاة، لا دقة ميدانية، ولا يدعي النظام توفير ماء.
- **المحاصيل الأربع:**
  - معادلة موازنة الماء الفيزيائية قوية جدًا (RMSE 0.661)، والنموذج الهجين يحسنها بفارق صغير (0.644).
  - كمية إعادة الملء الكاملة قد تتجاوز أكبر كمية رآها النموذج في التدريب، فتحذّر الواجهة من الاستقراء.
  - p من FAO-56 الجدول 22 (للخضار قيمة وسطى لأن النوع غير محدد).
- **البرمودا:** موقع واحد ومنطقتان بمعاملات تربة مفترضة؛ التقسيم الزمني لا يختبر التعميم المكاني.
- **الصور الـ12:**
  - مرجع بصري فقط، ولم تُستخدم في أي تدريب، ولا تُنسب لمناطق المحاصيل.
  - سبع منها في مجلد «صور برابغ ومدينة الملك عبدالله» وتُعرض تحت هذا الاسم فقط.
  - مؤشر الأخضر لوني تقريبي.
- **لا يوجد صمام أو متحكم متصل:** `valve_command` دائمًا `null`.
- **قبل أي استخدام حقيقي يلزم:**
  - حساسات معايرة.
  - FC/WP وعمق جذور مقاسة.
  - اعتماد مختص زراعي للقواعد.
  - وسوم ميدانية مستقلة.

  التفاصيل في [`docs/DATA_LIMITATIONS.md`](docs/DATA_LIMITATIONS.md).

## 10. الاختبارات

```powershell
py -3 -m pytest tests -m "not slow" -q            # 88 اختبارًا: وحدات + تكامل على خادم حقيقي وقاعدة مؤقتة
py -3 -m pytest tests -m slow -q                  # تشغيل المشروع من الصفر في مجلد مؤقت (عدة دقائق)
cd image_processing; py -3 -m pytest test_program.py -q   # 17 اختبارًا لمعالجة الصور
# اختبار الواجهة في متصفح حقيقي (Edge/Chrome) بعد تشغيل الخادم:

```

اختبار الواجهة ينقر الأزرار فعليًا ويتحقق من:
- تحميل الصفحات السبع وكل تبويب دون أخطاء JavaScript أو HTTP.
- حفظ التوصيات وزيادة عدد السجلات في SQLite.
- المحاكاة، وتصفية السجل، وتشغيل نموذج كل منطقة، وتحميل الصور.

نتائج آخر تشغيل في [`docs/TEST_REPORT.md`](docs/TEST_REPORT.md).
